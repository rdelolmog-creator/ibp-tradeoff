In src/reporter.py:

  def avoidable_cost_view(scenario_result, assumptions) -> dict
      Takes one ScenarioResult (from TradeOffEngine.run_scenario). Returns the
      four outputs with conversion cost split into avoidable and fixed:
        lost_sales_eur, excess_obsolescence_eur, working_capital_cost_eur,
        conversion_cost_avoidable_eur, conversion_cost_fixed_eur,
        total_avoidable_cost_eur, total_reported_cost_eur
      fixed = fixed_absorption_eur_line_month x horizon_months, read from
      assumptions, never hard-coded (D-062). total_avoidable_cost_eur is the
      sum of the four LEVER-RESPONSIVE outputs; total_reported_cost_eur adds
      the fixed absorption back for anyone who needs the full P&L number.
      Both are returned — never only one — because reporting only the avoidable
      figure without the reconciling total is how a plant controller ends up
      thinking the model lost €3.6M of their P&L (the exact failure mode D-062
      was written to prevent).

  def capacity_warning(line_id, levers, portfolio_summary_row) -> Optional[str]
      D-070. Given a proposed lever setting and that line's row from
      step08_portfolio_summary.csv, return a warning string if the setting
      resembles the region that produces a capacity breach, else None. Do NOT
      hard-code "L2" or a specific cover value — read worst_case conditions
      from portfolio_summary_row and flag when the proposed inventory_cover_weeks
      is within one grid-step of the line's worst-case breaching value AND
      any_capacity_breach is True for that line. Generalises to any line that
      develops the same pattern later, rather than encoding today's one
      finding as a permanent special case.

  def owner_view(scenario_result, sku_master, assumptions) -> pd.DataFrame
      Maps each of the four outputs to the accountable role, from
      assumptions — do not invent a mapping here if one already exists in
      config; if it does not exist, add ONE new assumptions.yaml block
      (owner_mapping: {lost_sales: "...", excess: "...", ...}) at role level,
      per D-011's stated principle (accountability at role level, not named
      individuals).

  def policy_brief(optimal_policy, sku_master, top_n=10) -> pd.DataFrame
      The SKUs with the largest saving_eur (Step 7), joined to their category
      and ABC class, formatted for a planner to act on directly — sku_id,
      category, abc_class, current-vs-optimal cover and service, saving_eur.
      This is the "so what do I actually change" artefact — Step 7 produced
      the optimum, this step makes it actionable.

  def portfolio_brief(portfolio_summary, lever_consistency) -> str
      A short plain-text summary: which lines are healthy, which line (if any)
      carries a capacity risk and under what condition, which lever
      directions are consistent vs line-specific. This is the paragraph a CFO
      reads before the four-output table, not a restatement of the tables.

  def export_artefacts(..., out_dir) -> dict[str, str]
      Writes avoidable_cost_summary.csv, policy_brief.csv, portfolio_brief.txt
      to out_dir. Returns the paths. No plotting library dependency here —
      Step 10 (Streamlit) owns visualisation; this step owns the numbers.
